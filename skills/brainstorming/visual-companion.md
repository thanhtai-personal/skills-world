# Visual Companion Guide

Use a visual/browser companion only when the user would understand the question better by seeing it than by reading it.

Good uses: UI mockups, wireframes, layout comparisons, architecture diagrams, spatial flows, and side-by-side visual design choices.

Stay text-first for requirements, scope, conceptual trade-offs, technical decisions, and ordinary clarifying questions. A UI topic is not automatically a visual question.

If the runtime offers a visual companion, ask just-in-time before opening it, then use it only for the visual decision at hand. When returning to text-only discussion, stop presenting stale visual choices as if they were still active.

Keep visual options focused (usually 2–4), use real content when it affects the decision, and iterate the current visual question before moving on.
